# 2026-05-21 工作附记

今天把 Notiee 从 PRD 落到了一个可以跑、可以点、可以继续生长的 iOS MVP 骨架。

## 完成内容

- 搭好了原生 SwiftUI App 结构，包含 Today、拍记、记录、我四个底栏入口。
- 补齐了核心领域模型：日程、拍记记录、待办事项、AI 处理状态。
- 实现了日程感知匹配逻辑：拍照时可以根据当前时间自动关联课程/会议，无命中时归入未分类。
- 修复了模拟器首屏比例异常，通过 Launch Screen 配置让 App 按完整屏幕尺寸渲染。
- 做了 Today 控制中心的首版样式：当前日程、今日时间轴、待办事项、今日记录。
- 做了拍记页的极速相机占位交互：快门生成记录，记录进入本地 Store，并保留未分类兜底。
- 加入了 JSON 本地记录持久化，拍记记录可以在本地保存和重新载入。
- 做了记录页：系统文件夹计数、搜索、全部记录列表，以及记录详情页。
- 记录详情页已展示分类/课程、标题、AI 状态、图片占位、AI 摘要、待办事项和 OCR 原文。
- 做了设置页：默认启动页选择、文本处理模型配置、图像识别模型配置、连接状态提示。
- AI API Key 已走 Keychain 保存，普通 UserDefaults 只保存供应商、接口地址、模型名等非敏感字段。

## 验证记录

- 单元测试覆盖了日程匹配、Today 数据筛选、拍记记录生成、Store 持久化、记录详情 ViewModel、设置页持久化和 API Key 存储策略。
- 当前完整测试为 17 个用例，最近一次验证全部通过。
- 模拟器中已检查 Today、记录详情、设置页与 AI 配置页的主要路径。

## 设计取舍

- 当前版本优先保持原生 SwiftUI 风格，尽量使用系统组件、SF Symbols 和 Form/List/NavigationStack 等 iOS 习惯。
- AI 连接测试暂时只做本机字段完整性校验，还没有向真实模型服务发请求。
- 相机、OCR、摘要生成、日历导入仍是后续真正接入阶段，目前用可测试的本地模型和 mock 路径撑住主流程。

## 下一步建议

- 把 Today 页也接入同一个 `NotieeStore`，让拍记后的记录能即时反映到 Today。
- 接入真实相机捕获与相册导入。
- 给 AI 配置页增加真实请求测试，并把 OCR/摘要/待办提取接入后台处理队列。
- 增加课程/文件夹二级详情页，按周次和日期组织记录。
