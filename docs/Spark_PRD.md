## 一、概述

Spark 是 Notiee 内置的「个人知识 AI」功能，允许用户通过自然语言对话的方式，从自己积累的所有拍记记录（NoteRecord）中快速检索信息、获得答案、总结知识。它将静态的记录库转化为可交互的智能知识助手。

**核心理念：** 用户的每一次拍记都在为 Spark 积累资料。用得越久，Spark 越懂你。

---

## 二、目标与价值

| 目标 | 说明 |
|------|------|
| 提升信息检索效率 | 用户无需手动翻阅大量记录，直接提问即可找到答案。 |
| 激活存量数据价值 | 让历史拍记不再是「沉睡的档案」，而成为可复用的知识资产。 |
| 增强产品粘性与差异化 | 形成「记录 → 积累 → 智能问答」的闭环，区别于普通笔记/相机应用。 |
| 为后续知识图谱/主动推荐奠定基础 | Spark 可作为更高级 AI 功能的入口。 |

---

## 三、用户场景

| 场景 | 示例提问 |
|------|----------|
| 回顾会议决定 | 「上周产品评审会确定的 Deadline 是什么？」 |
| 查找特定知识点 | 「最近三个月我拍过哪些关于 SwiftUI 动画的内容？」 |

| 提取待办 | 「从本周的会议记录里，我还有哪些未完成的待办？」 |
| 时间范围查询 | 「去年 12 月拍摄的那张白板照片里写了什么？」 |

## 四、功能需求

### 4.1 入口与界面

- **入口位置：** 底部 Tab 栏新增 Spark 标签（可替换原有某个次要标签，或作为第五个标签）。
- **界面组成：**
  - 顶部标题栏：显示「Spark」及副标题「你的知识 AI」
  - 对话消息列表：用户提问气泡 + AI 回答气泡（支持 Markdown 渲染）
  - 底部输入区：文本输入框 + 发送按钮
  - 建议问题区域（可选）：首次进入或无对话时，显示 2-3 个示例问题

### 4.2 问答流程（核心）

1. 用户输入自然语言问题。
2. 系统在本地执行混合检索（关键词 + 语义相似度），从 NoteRecord 的 `title`、`summary`、`detailedContent`、`ocrText` 字段中召回最相关的 **Top‑5** 记录。
3. 将检索到的记录内容（截断到合理长度）与用户问题一起构造成 Prompt，发送给云端 LLM（沿用 Notiee 已配置的 AI 模型）。
4. LLM 返回答案，并在答案底部显示**引用来源**（每条引用显示拍记标题、时间，可点击跳转）。
5. 对话历史保存在本地（轻量级，最多保留最近 20 轮）。

### 4.3 检索实现（MVP）

- **关键词检索：** 使用 NSPredicate 或 Searchable 对文本字段进行前缀/包含匹配（不区分大小写）。
- **语义检索（可选，增强体验）：** 使用本地 `NLEmbedding`（iOS 18+ 提供）对用户问题和记录片段生成向量，计算余弦相似度。若设备不支持，则仅使用关键词检索。
- **混合排序：** 关键词匹配权重 0.4 + 语义相似度权重 0.6，取综合得分最高的 5 条。

### 4.4 AI 回答要求

- **Prompt 设计：** 明确要求 LLM 仅基于提供的记录内容回答，不能编造外部知识。
- **答案结构：** 先直接回答，再以列表形式列出参考的拍记（含标题和日期）。
- 如果检索结果与问题不相关，应告知「未在你的记录中找到相关信息，请尝试换个问法」。

### 4.5 隐私与安全

- 检索过程完全在设备本地执行（不上传用户原始记录）。
- 仅用户问题 + 检索到的记录片段会上传到 AI 模型 API（沿用现有 Notiee 的 AI 配置与安全机制）。
- 首次进入 Spark 时弹出隐私说明：「你的拍记内容仅用于本设备检索，不会用于任何训练或分享。」

## 五、技术要点

| 模块 | 实现方案 |
|------|----------|
| 检索 | 关键词 + `NLEmbedding`（iOS 18+）混合检索 |
| 对话管理 | 本地 JSON 文件存储历史消息（上限 20 条） |
| AI 调用 | 复用现有 `RealAIProcessingService`，新增 `sparkChat` 方法 |
| 引用跳转 | 通过 `NoteRecord.id` 导航到 `RecordDetailView` |
| 性能 | 检索需在后台队列执行，主线程仅更新 UI |

## 六、用户流程（用户故事）

**首次使用：**
用户打开 Spark → 看到欢迎语和示例问题 → 点击示例或输入问题 → 获得回答 → 点击引用查看原始记录。

**日常使用：**
用户输入问题 → 等待 1-3 秒 → 显示回答 → 可继续追问（上下文保留）。

**无结果场景：**
用户问题找不到相关记录 → AI 回复「未找到」→ 建议用户尝试其他关键词或先去拍记。

## 七、非功能需求

| 需求 | 指标 |
|------|------|
| 响应时间 | 检索 + AI 调用总时长 ≤ 5 秒（正常网络） |
| 检索准确率 | Top‑5 命中率 ≥ 85%（人工抽样测试） |
| 离线支持 | 无网络时提示「网络不可用，无法进行 AI 问答」，但检索结果可预览（不调用 AI）。 |
| 内存占用 | 对话历史加载 ≤ 10MB |
| 可扩展性 | 未来可替换 embedding 模型、增加多轮对话摘要压缩。 |

## 八、背景动效设计

### 8.1 色彩体系

界面采用单色基底：

- 浅色模式下为纯白（`#FFFFFF`）。
- 深色模式下为深黑（`#000000`）。

两种强调色 `#5CAEFA` 与 `#53FAAB`，仅以柔和半透明渐变团块的形式悬浮于背景之上。

### 8.2 空闲态

彩色渐变团块以缓慢、有机、流动的方式独立运动。运动轨迹自然且不可预测，如同悬浮在水中的彩色墨水，或极光在大气中漂移。运动幅度极其微弱且不分散注意力，营造出一种智能与灵动的感觉，而不从对话中抢走焦点。

### 8.3 聚焦态（输入框获得焦点）

当文本输入框获得焦点时，背景动效立即做出响应：原本独立运动的色彩团块开始向输入区域汇聚，如同被磁力吸引般微微加速。颜色聚集并浓缩在输入区域附近，亮度与密度增加，同时保持柔和的模糊外观。

### 8.4 发送态（按下发送按钮）

当用户按下发送按钮，聚集的色彩能量向上释放。汇聚的渐变团块迅速膨胀并扩散至整个界面，形成流畅的向上涌动 —— 如同流动的光、液态能量，或温和的极光喷发。运动优雅而非爆发性，留下淡雅的色彩尾迹，逐渐溶解并回归到背景空闲态。

### 8.5 整体感受

整个动效应给人以下感觉：

- 智能的
- 响应式的
- 有机的
- 平静的
- 高级的
- Apple 级别的流畅度

**避免：**

- 粒子特效
- 生硬的过渡
- 霓虹光效
- 过高的亮度
- 明显的循环轨迹

动效应像是一个有生命的 AI 存在在回应用户交互，而非装饰性的视觉效果。
